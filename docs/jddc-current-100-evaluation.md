# 原JDDC 100条阶段测试集：当前知识库评测

## 数据与范围

2026-10-10运行。不是新增7条或原12条：使用原 `backend/data/evaluation/splits/test.json` 的全部100条，每类20条。逐项验证ID、Query、原category及顺序完全一致，未挑选较容易的问题。原15块演示知识标签已失效，保留旧文件并针对当前47块京东/淘宝资料进行两遍模型核验，输出 `backend/data/evaluation/jddc_test_current_100.json`；SHA与数据身份记录在相邻metadata.json。

新标签含正确来源、参考答案、是否需要知识工具和允许的参数类别。它们是AI候选标注，不是人工金标准。工具选择标签独立于知识可回答性，不强制100条全部调用知识工具；生成模型只收到原Query，不收到标签。原分类保留作数据身份，不盲目作为参数正确性的唯一标准。

当前标签有4条可回答、96条不可回答；32条需要知识工具，68条应澄清/说明无法处理个人订单或操作请求等。本实验仅有知识工具，不代表完整五Agent路由、订单或售后任务完成率，也不是未见过的盲测。

Recall采用逐可回答Query宏平均，Top5命中分别为2/2、1/1、2/7、1/4，平均63.39%。4条都至少找到一个正确块，但不等于证据全部召回；标注7个相关来源的样本在Top5下无法全部命中，整体Recall@5理论上限92.86%。这些来源是否冗余、是否都必要，仍需人工复核。数据稀少，不能宣称稳定检索收益。旧95.45%来自旧知识库和旧标签，不能直接比较。

96条不可回答问题都返回了候选，说明默认准入仍过宽。RRF分数不是可回答概率；此次只测量，不根据测试集调阈值以制造提升。

本机实验，检索和工具实验同时启动，共享资源；不是隔离性能压测。回答质量在直接检索阶段没有调用评审，原生检索报告中的回答分数0表示未测，不能解释为质量为0。

严格任务通过要求无运行/评审错误、工具选择正确、参数通过，以及正确性、忠实度、完整性三项评分均不低于0.7。它包含合理拒答与澄清，但不代表真实订单/售后任务完成率。P95含在线模型、实际工具检索和最终作答，不含标注、参数评审与回答评审。

回答指标是0到1的模型评分平均值，不能称作人工准确率或拒答准确率。生成与评审使用同配置模型，存在自评偏差；大量不可回答样本上的拒答也参与平均，引用评分包含无引用场景，不能宣称“真实引用全部正确”。本轮没有单独计算基于明确拒答标签的拒答准确率。

最终100条在线用量完整，但不包括废弃轮次、标注和评审用量，也不等于本次实验全部账单或完整会话成本。金额需要服务商实际输入/输出价格，未填价格时不能把null解释为零费用。

## 失败轮次与恢复记录

最初服务商HTTP402导致89条在线失败，仅11条完成回答。充值后复用8条完整样本、重跑92条，100条在线完成，但8条参数评审JSON格式错误。后续只重试基础设施/评审失败项，已完成的低分样本不重跑。

再次续跑时原Milvus容器停机，启动后连续出现`panic: etcdserver: leader changed`。原容器及绑定数据目录未删除；新建同版本隔离实验容器`milvus-eval-20261010`和Docker命名卷，在相同本地端口同步同一47块知识与HNSW配置后，补齐8条失败样本。没有以模拟向量或内存检索代替Milvus。最后92条复用、8条补齐；再对全部已完成结果做一次纯统计汇总，无新增在线模型调用。

基础设施变化、续跑及本地并发资源使这些延迟只适合作为本机诊断。配置指纹覆盖模型与检索设置，不覆盖容器存储介质、代码版本和全部运行环境，不能据此宣称严格性能对比。原容器仍需单独排障，实验容器不是正式部署迁移。

核对明细发现两处统计缺陷并保留原始记录：无模型响应的失败请求不能算正确不调用工具；误调用工具的样本也应纳入参数统计。后者有3条参数已评审通过却曾记null，现依据原call结果修正为true，参数统计从13/84修正为16/87，未改模型输出、标签或评分。新增回归测试保障误调用不会漏出参数分母。

## 结论与下一步

当前主要问题是知识工具过度调用（55条）、严格参数契约通过率低，以及资料不足时仍添加未被支持的建议。检索阶段无答案错误召回96/96进一步说明，返回相关候选不等于能够回答。

下一步先人工复核候选标签与失败案例，在开发集改进工具选择、分类过滤、证据不足判定和参数改写，再用独立新样本验证。不要在这100条上调参后继续声称盲测收益；仅4条可回答样本不足以证明稳定召回水平。

最终报告及逐条回答位于`docs/evaluations/jddc-current-100-2026-10-10/runtime_report.json`和`runtime_results.jsonl`，失败与修正前轮次位于同目录`resumed_attempts/`及原有incomplete文件。原始记录包含问题、工具参数、检索来源、实际回答、质量理由、耗时和Token，便于逐项复核。
