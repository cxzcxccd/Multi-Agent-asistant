# Frontend Demo

## 交付状态

- 产品方案已由用户确认，当前交付可运行的前端演示。
- 页面：买家客服、客服工作台、开发者与评测、数码旗舰店。
- 所有商品、订单、物流、售后和知识资料均为演示数据。
- 普通对话和商品咨询调用 FastAPI 和 LangGraph；订单、售后、人工服务及评测仍由预设脚本驱动。
- 浏览器交互测试验证的是 Demo 行为；评测页百分比为虚构示例，不能当作真实 Agent 成绩。
- **待用户体验确认；尚未进入技术方案设计。**

## 启动与访问

先启动并配置后端，再在 `frontend` 目录运行 `npm ci` 和 `npm run dev`，打开
`http://127.0.0.1:5173`。把 `VITE_CHAT_MODE` 设置为 `script` 可以运行完全独立的
脚本演示；默认的 `backend` 模式会把普通对话和商品咨询发送给本地后端。“你是谁”
和“你好”也会调用模型，无须输入商品关键词。

| 页面 | 地址片段 | 主要操作 |
| --- | --- | --- |
| 买家客服 | `#chat` | 咨询、查单、申请售后、查看结果、转人工 |
| 客服工作台 | `#workbench` | 接管／回复／恢复 AI、审核售后 |
| 开发者与评测 | `#lab` | 执行事件、评测预览、资料与演示控制 |
| 数码旗舰店 | `#shop` | 全店商品陈列、搜索、分类、价格／库存筛选、详情、返回客服 |

手机尺寸下，左上角菜单用于切换页面，聊天标题栏的订单图标用于打开服务速览。刷新后保留当前浏览器记录；演示控制中的重置操作需要确认。

## 数据基准

业务时间固定为 2026-09-15；消息发送时间与执行耗时是本地实际界面操作时间，两者用途不同。

- 买家 A：林同学，订单 10001、10002、10003、10004。
- 买家 B：陈同学，订单 20001。
- 订单 10001：AirBeat Pro 耳机，运输中，有三个物流节点。
- 订单 10002：Studio One 耳机，已签收，用于售后。
- 订单 10003：LinkHub 扩展坞，历史订单。
- 订单 10004：两件 PowerMini 充电器，待发货，无物流节点。
- 订单 99999：不存在；和不属于当前买家的订单使用统一不可查提示。
- 商品共 12 个，覆盖耳机、充电器、扩展坞以及有货／缺货场景。

## 推荐演示流程

### 1. 商品咨询与资料

输入 `推荐 300 元以内的耳机`，查看预算内商品、价格和库存。展开参考资料可查看说明书摘录。

输入 `了解 AirBeat Lite 无线耳机`，应提示当前缺货，不承诺补货时间。

输入 `LinkHub 6 合 1 扩展坞可以用在我的电脑上吗`，应先追问设备信息；回复 `MacBook Air M2` 后，仍明确现有资料不能证明具体型号完全兼容。

### 2. 订单与隔离

输入 `查一下我的订单`，从候选订单选择 10001，查看详情和物流。

输入 `查询订单 10004`，应展示无物流状态；输入 `查询订单 20001` 和 `查询订单 99999`，买家 A 均收到统一不可查提示。

通过右上角切换到买家 B 后，可以查询 20001；切换不会继承买家 A 的会话内容。

### 3. 售后申请与审核

1. 买家 A 输入 `订单 10002 耳机有一边没声音，想退货`。
2. 修改申请类型或问题描述；草稿可以取消，取消不创建已提交申请。
3. 点击确认申请内容，在弹窗中核对订单、商品、类型和原因，勾选确认后提交。
4. 当前状态为待人工审核；再次申请同一笔待审订单不会重复建单。
5. 进入客服工作台 → 售后审核，选择批准或拒绝，填写必填审核意见。
6. 回到买家会话，看到审核结果与原因；批准不显示为资金退款到账。
7. 刷新页面后仍可查看申请和审核记录。

### 4. 人工接管

点击转人工后，自动回复暂停，买家仍可补充问题。

在客服工作台选择该会话并接管，输入人工回复。买家页可看到客服小周的回复；即便之前的模拟查询还在执行，也不会继续补发自动回复。

只有客服明确点击恢复 AI，买家才重新获得自动回复。结束服务后，买家可以开始新会话。

### 5. 执行记录与故障恢复

在开发者页查看一次运行的模块、步骤、工具名称、检索资料、状态和结果。显示的是外部动作，无内部思维链。

在演示控制中选择工具查询失败，再查订单；界面应提示失败且不出现成功订单卡片。关闭故障后点击重试。

选择知识资料不足，再询问具体商品；应提示缺少依据，不编造功能说明。

停止输出只终止当前自动回答，不撤销已提交的售后申请。执行途中刷新会提示上次处理中断，并提供重新查询入口。

### 6. 评测预览

查看 Prompt V1／V2 的示例比较、分母和案例。播放评测演示仅呈现界面状态，不运行真实评测。

模型、真实延迟、Token 和费用显示未接入／未测量／不可用；MCP 指标显示不适用。

### 7. 数码旗舰店与工单往返

- 点击左侧数码旗舰店进入商城式全量商品网格，默认展示 12 件商品。
- 可以按耳机／充电器／扩展坞分类，搜索名称和参数，按价格排序、筛选区间及仅看有货。
- 商品主图和名称可打开详情，查看价格、库存、参数、说明书摘录及售后规则。
- 买家选择咨询商品后回到当前会话；已输入但未发送的内容保留。
- 从客服工作台进入时，可以将商品资料追加到当前人工回复草稿，不自动发送，且保留选中的客户会话。
- 直接返回工作台时，保留此前选中的售后审核或会话处理标签。
- 商品图为生成的虚构外观示意；完整提示词及保存路径见 `catalog-assets.md`。

陈列结构参考 [京东商品搜索页](https://i-search.jd.com/Search?enc=utf-8&keyword=%E8%80%B3%E6%9C%BA)可见的分类、价格和商品信息组织方式。淘宝页面在本环境无法直接读取，因此没有声称复刻其当前页面。界面采用项目自己的品牌、数据和样式，不使用真实商城的销量、评价或商家背书。

## 验证范围与记录

脚本演示的自动化测试位于 `frontend/tests/demo.spec.ts` 与 `frontend/tests/shop.spec.ts`，使用真实 Chrome 浏览器进行交互，覆盖：

1. 商品筛选、来源展示、缺货与无匹配结果。
2. 兼容性追问与证据不足。
3. 多订单选择、物流和无物流状态。
4. 模拟买家间的订单和会话隔离。
5. 售后原因补充、取消草稿。
6. 修改申请、确认提交、审核与刷新恢复。
7. 重复提交、重复申请保护，拒绝原因必填。
8. 人工接管阻止延迟回复，恢复后继续自动服务。
9. 模拟工具失败与关闭故障后的重试。
10. 资料不足及对应检索事件。
11. 刷新中断任务与恢复查询。
12. 评测示例标识与重置确认。
13. 桌面 1440 × 1000、移动端 390 × 844 的页面访问、截图、横向溢出及浏览器错误检查。
14. 移动端售后提交和人工审批。
15. 已打开的两个页面之间同步运行状态和人工接管。
16. 主动停止、新会话上下文隔离。
17. 全店陈列、分类、价格排序、库存筛选、空结果恢复及图片可用性。
18. 搜索商品、查看详情、继续原会话咨询。
19. 客服保留选中会话和已有草稿，引用商品不自动发送。
20. 往返店铺保留售后审核标签。
21. 移动端店铺、商品详情及无横向溢出检查。

构建检查包括 TypeScript 类型检查和 Vite 生产构建，格式检查使用 Prettier。测试覆盖演示用例，不能替代正式后端权限校验或真实 AI 评测。

### 本次验证结果

- TypeScript 检查及 Vite 生产构建：通过。
- Prettier 格式检查：通过。
- 脚本演示包含 21 项 Chrome 浏览器回归。`backend-chat.spec.ts` 另行验证后端模式的普通对话、追问、错误重试、会话恢复和停止行为；通过拦截 HTTP 响应验证请求链路，不消耗模型额度。
- 手动检查桌面商品陈列、商品详情和移动端截图，图片正常显示，核心操作无横向溢出。
- 修复了浏览器排队的旧存储事件覆盖较新的接管状态的问题；刷新只恢复本标签页拥有的中断任务，并保存恢复结果。
- 页面首次访问时才初始化，访问后保留状态；评测页回归用例明确切换执行记录标签，以适应新增的标签保留行为。
- 默认测试使用单 worker，降低本机同时运行浏览器、开发服务和测试时的资源争用。

## 已知边界

- 脚本模式和模拟业务使用有限的关键词和上下文规则；后端模式的普通对话及商品咨询由真实模型回答。
- 前端模拟归属、确认和审核流程。开发者工具可以修改浏览器数据，因此不能用于真实身份和权限保障。
- 数据按浏览器来源保存；换浏览器、清理站点数据或使用不同主机名会得到另一份记录。
- 同一来源的已打开页面通过浏览器存储事件同步，不具备服务端事务、跨设备协作或强一致性保证。
- 演示期间不上传文件、不连接店铺、不调用支付系统，也不执行真实退款。
- 本次测试使用本机 Chrome；没有宣称已经验证所有浏览器、真实手机设备或生产部署。
- 真实 Agent Evaluation、LangGraph、RAG 和 MCP 的实现仍在后续阶段。
